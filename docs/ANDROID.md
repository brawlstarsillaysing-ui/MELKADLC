# Android: сборка и ограничения

Оригинал: `skinchiki.apk` из V1.1.0, SHA-256 `639e45b129443b86fd35e4f03487547dce599a52443a37ba4ead22ceb082cb6e`.

Package `com.local.moduleloader.agnes`, исходный minSdk 26 / targetSdk 28, только `arm64-v8a`. Технические имена библиотек и исходного Activity сохранены. Новый launcher — `com.melkadlc.GateActivity`; исходный Activity теперь не экспортирован.

Установлены две независимые проверки: сертификат APK и SHA-256 `launch.sh`/обеих библиотек. В версии 0.15 сохраняется сертификат предыдущей MelkaDLC; обновляются ожидаемые хеши модуля и launch.sh после ограниченного изменения брендовых строк. Проверки, ошибки и ветвления не удаляются. Новая подпись явно разрешена владельцем; сертификат оригинала восстановить из APK невозможно.

Инструменты: Java 21, Android SDK Platform 35 (`android.jar`), Build Tools 35.0.0, Apktool 3.0.3, Eclipse ECJ 3.40.0, Python 3.12. APK и инструменты загружаются из официальных источников соответствующих проектов, подпись — `apksigner` Android SDK. Debug keystore не используется.

```sh
python android/build.py \
  --original /PATH/skinchiki.apk \
  --work /PATH/NEW_EMPTY_BUILD_DIRECTORY \
  --out /PATH/MelkaDLC.apk \
  --apktool /PATH/apktool.jar \
  --android-jar /PATH/android-35/android.jar \
  --ecj /PATH/ecj.jar \
  --build-tools /PATH/build-tools/35.0.0 \
  --keystore /PRIVATE/melkadlc-release.p12 \
  --password-file /PRIVATE/password.txt \
  --certificate /PRIVATE/certificate.der \
  --api-url 'ACTUAL_HTTPS_API_ORIGIN'
```

API по умолчанию — `https://melkadlc.onrender.com`. Пустой/HTTP адрес отклоняется при сборке и не даёт свободного доступа на устройстве. В APK нет серверного административного секрета. Не добавляйте `/v1` к origin: клиент добавляет маршрут сам.

`android/build.py` проверяет оригинальный хеш и отказывается перезаписывать существующий каталог сборки или APK. Параметр `--certificate` должен соответствовать приватному ключу keystore. После сборки выполняются криптографическая проверка APK и проверка разрешённых изменений модуля и pins сценария; неизменность остальных инструкций проверяется android/verify.py. Публичный отпечаток новой подписи: `684222e0f663d951bf31b16637e5d1d4b424341344e3bd89b64c76d4f9273d27`.

Интеграция с API:

- `POST /v1/activate`: ключ и случайный UUID установки; никаких IMEI.
- `GET /v1/license`: выданный сессионный bearer token; хранится зашифрованно Android Keystore AES/GCM.
- Сервер определяет даты; отсчёт в UI использует `elapsedRealtime` и серверное время.
- Проверка обновляется каждые 20 секунд. Ошибка проверки закрывает доступ; допуск автоматически прекращается не позднее 45 секунд после последней проверки и срока ключа. После перезапуска процесса нужна новая серверная проверка.
- Сброс привязки инвалидирует сессию и не продлевает ключ.
- API принимает только HTTPS, не следует redirect при передаче токена; приложение не содержит BOT_TOKEN/SERVICE_TOKEN и не подключается к PostgreSQL.
- Android-клиентский gate не заменяет серверную авторизацию защищённых серверных ресурсов.

Добавлены ссылки на реального бота и канал @MelkaDLCRealese, информация об обновлениях без GitHub-ссылок и отчёт с версией/Android API/состоянием проверки. В новый отчёт не включаются ключ, токен, Telegram ID, UUID установки и исходные root-логи.

До заявления о сохранении поведения необходимо проверить на ARM64-устройстве: установку с новой подписью, первый запуск, splash, отображение, поворот, кнопки, журнал, штатный root-сценарий исходного приложения. Для лицензионной сборки дополнительно проверить сеть, пять Trial последовательно, второе устройство, сброс, блокировку, истечение и офлайн. Эти проверки нельзя заменить совпадением хешей библиотек.
