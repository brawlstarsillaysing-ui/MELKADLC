# MELKADLC CONTROL CENTER

`/admin` доступен разрешённым Telegram ID. Каждая кнопка и каждый API-запрос повторно проверяют права на сервере. Просмотр разделов, статистика и списки выполняются Inline-кнопками; изменения задаются структурированным JSON, проходят предпросмотр и отдельное подтверждение. Это рабочий административный интерфейс, но не отдельная веб-панель с графическими формами.

В боте выберите `Действие / Action` и отправьте JSON. `request_key` бот добавит сам; HTTP-клиент обязан передавать уникальный `request_key` и повторять его при повторной попытке того же действия. Изменённые параметры с тем же ключом отклоняются.

Обязательны `action`, `target`, `reason` (не менее 3 символов). В примерах замените USER_ID/UUID реальными значениями. Числовой `user_id` передаётся числом, не строкой. Не используйте примеры как реальные платёжные реквизиты.

| Действие | Дополнительные поля |
|---|---|
| `ban`, `unban` | `user_id` |
| `adjust_balance` | `user_id`, `amount`: положительное/отрицательное изменение **бонусного** баланса |
| `grant` | `user_id`, `duration_seconds`, необязательно `device_limit`, `count` (1–100) |
| `license_update` | `target` = UUID лицензии; `delta_seconds`, `status`, `device_limit` |
| `reset_device` | `target` = UUID лицензии; принудительный сброс без расходования пользовательского лимита |
| `payment_confirm`, `payment_reject` | `target` = UUID заявки; также доступны кнопки под чеком |
| `refund` | `target` = UUID покупки; возврат на внутренний баланс, отзыв ключа, сторно реферального бонуса |
| `plan_update` | `target` = ID тарифа; `name`, `amount`, `duration_seconds`, `active`; для нового тарифа нужны имя, сумма и срок |
| `promo_create` | `target` = код; `reward_type`, `amount`, `expires_at` с UTC offset, `max_uses`, `per_user_limit`, необязательно `allowed_users` |
| `promo_disable` | `target` = код |
| `setting` | `target` = ключ настройки; `value` = строка |
| `support_reply` | `target` = UUID обращения, `value` = ответ |
| `support_close` | `target` = UUID обращения |
| `broadcast_create` | `value` = текст; необязательно `media_type` (`photo`/`video`) и `file_id`; `button_text` и HTTPS `button_url` вместе |
| `broadcast_confirm`, `broadcast_cancel` | `target` = UUID подготовленной рассылки; бот показывает отдельную кнопку отправки |
| `admin_add`, `admin_remove` | `user_id`; отключаемый ID удалите также из `ADMIN_IDS` |

Для промокодов `balance` — бонусные UAH, `license` и `extension` — целое число секунд, `discount` — проценты до 100. Продление применяется к действующей лицензии, указанной пользователем. Скидки не складываются; используется наибольшая действующая, один раз на покупку. Бонусные средства и скидки не считаются внешним поступлением денег.

Настройки: `payment_recipient`, `payment_card`, `channel_url`, `support_url`, `self_reset_limit`, `latest_version`, `update_notes`, `update_url`. Telegram-ссылки должны быть реальными `https://t.me/...`; вымышленные ссылки по умолчанию отсутствуют.

Пример изменения цены:

```json
{"action":"plan_update","target":"30","amount":"250.00","duration_seconds":2592000,"reason":"Update monthly plan"}
```

Пример промокода (дату задайте в будущем):

```json
{"action":"promo_create","target":"MELKA2026","reward_type":"balance","amount":"50.00","max_uses":100,"per_user_limit":1,"expires_at":"2026-12-01T00:00:00Z","reason":"Launch promotion"}
```

Для подтверждения платежа сначала проверьте реальное поступление в своём банковском приложении. Прикреплённый файл только доказательство для ручного рассмотрения; он никогда автоматически не зачисляет деньги. После решения статус виден пользователю в списке заявок.

`refund` возвращает покупку на внутренний баланс. Фактический банковский возврат выполняется оператором отдельно; в статистике внешнее поступление и внутренние операции не смешиваются. Если реферальный бонус уже потрачен, его сторно создаёт `bonus_debt`: новые бонусы сначала гасят долг, покупки временно блокируются. Уменьшение срока не меняет дату активации и не перезапускает подписку.

История активаций, промокодов, финансов и журнал администратора доступны в списках с пагинацией. Слишком длинный административный список отправляется JSON-файлом. Отзыв вместо удаления сохраняет связи и историю операций.
