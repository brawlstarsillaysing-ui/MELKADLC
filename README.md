# MelkaDLC

Обновление существующего репозитория и APK из Release **V1.1.0**. Исходный `skinchiki.apk` не заменяется.

## Текущее состояние — 0.16-menu

- Новая сборка — `MelkaDLC-menu.apk`; предыдущие APK в Release V1.1.0 сохраняются.
- В меню и загрузочном экране модуля изображение кота заменено на значок M из APK. В заголовке — `MelkaDLC`.
- На загрузке M раскрывается в «Melka DLC» и сворачивается обратно. Переход к полному меню и время загрузки остаются под управлением исходного модуля.
- Подписи `Zenin.cc`, Telegram и известных внешних TG-ссылок скрываются при отрисовке. Удаление самих кликабельных областей закрытого UI не подтверждено; это не заявляется полным удалением кнопок.
- Лицензирование, HTTPS API `https://melkadlc.onrender.com` и получение ключа в `@MelkaDLCtrialbot` сохранены. Инструкции проверки лицензии совпадают с 0.15, кроме отображаемого номера версии.
- Версия — versionCode 21, сертификат совпадает с предыдущими MelkaDLC. Можно установить поверх 0.15; затем полностью перезапустить игру для загрузки нового модуля.
- Backend, бот и данные сервера не меняются. Проверки и ограничения: [docs/UPDATE-0.16.md](docs/UPDATE-0.16.md). Физический ARM64-телефон с игрой и root в этой среде недоступен.

## Запуск на сервере

Нужны Docker Compose, реальный домен и порты 80/443. Время хранится в UTC, деньги — `NUMERIC/Decimal`, валюта — UAH.

1. Скопируйте `.env.example` в `.env`. Файл уже исключён из Git.
2. Установите зависимости (`python -m venv .venv`, `.venv/bin/pip install .`) и выполните `.venv/bin/python scripts/generate_secrets.py`. Сохраните значения в `.env`, не в GitHub.
3. Задайте пароль PostgreSQL и соответствующий `DATABASE_URL`, `BOT_TOKEN` из BotFather, `BOT_USERNAME`, список `ADMIN_IDS` через запятую, `PAYMENT_CARD`, **реальное имя получателя** `PAYMENT_RECIPIENT`, домен `API_DOMAIN`. `API_BASE_URL=http://backend:8000` используется только ботом внутри Docker-сети.
4. `docker compose up -d --build`. Backend применит миграции, создаст начальные тарифы 20/90/250/600 UAH и начальных администраторов.
5. Проверьте `/health` через HTTPS и отправьте боту `/start`. Для уведомлений администратор тоже должен сначала открыть бота и отправить `/start`.
6. Внешний Caddy публикует только `/v1/*` и `/health`; служебные маршруты доступны боту внутри сети и требуют `SERVICE_TOKEN`.

Настройте доверенные reverse proxy через `FORWARDED_ALLOW_IPS`; не доверяйте произвольному `X-Forwarded-For` от внешнего клиента. Не публикуйте порт 8000 напрямую при использовании Caddy.

Не запускайте несколько polling-процессов для одного токена. Состояние диалогов бота хранится в памяти; после перезапуска пользователь начинает диалог заново, а все ключи, лимиты, платежи, чеки и покупки остаются в PostgreSQL. Чек можно повторно приложить из списка заявок.

## Render / ngrok

Пошаговая настройка: [docs/RENDER.md](docs/RENDER.md). Репозиторий содержит `render.yaml`. Создание платных ресурсов выполняется владельцем после проверки актуального тарифа хостинга.

ngrok подходит для временной проверки работающего локального backend; PostgreSQL и бот при этом также должны работать. Не направляйте внешний туннель на незащищённые административные инструменты. URL туннеля может измениться; APK со старым адресом потребуется перенастроить и пересобрать.

## Администрирование

Команда `/admin` проверяет Telegram ID на сервере, а не наличие кнопки. Все изменения проходят предпросмотр и подтверждение. Операции идемпотентны, причины записываются в аудит. Схемы и примеры всех действий: [docs/ADMIN.md](docs/ADMIN.md).

Новые `ADMIN_IDS` добавляются при запуске. Для отключения администратора используйте `admin_remove` и удалите ID из окружения, иначе следующий запуск вновь добавит его. Начальные тарифы не перезаписывают внесённые изменения. Изменение реквизитов: `setting`; цен: `plan_update`.

## Android

В `android/` находятся исходники нового интерфейса и воспроизводимый patch/build-процесс для проверенного оригинального APK. Это не исходный Gradle-проект нативного приложения: его владелец не предоставил.

[Инструкция сборки и подключения API](docs/ANDROID.md). Сохраните приватный резервный комплект нового сертификата: без него будущие сборки снова потребуют переустановки. Приватный ключ и пароль не публикуются в репозитории или Release.

## Тесты и резервное копирование

```sh
pip install '.[test]'
# Создайте отдельную базу с суффиксом _test. Рабочую БД использовать нельзя.
TEST_DATABASE_URL='postgresql+psycopg://USER:PASSWORD@HOST:5432/melka_test' python -m pytest -q
ruff check backend telegram_bot tests android/build.py scripts
python android/native-ui/test_ui.py
alembic check
```

Тестовый набор отказывается работать без явно указанной изолированной БД `_test`; он очищает только её таблицы. `scripts/backup.sh` создаёт согласованный `pg_dump -Fc`. Настройте регулярный запуск, шифрованное внешнее хранение и проверку восстановления. Восстановление: остановить API/бот, создать пустую БД, выполнить `pg_restore --no-owner --dbname ...`, вернуть те же ключи шифрования и HMAC, запустить сервисы. Никогда не заменяйте `KEY_HASH_SECRET`/`KEY_ENCRYPTION_SECRET` без миграции данных.

Рассылки имеют сохранённые статусы доставки и ограничение частоты. Telegram не поддерживает транзакционную exactly-once отправку: авария между отправкой и фиксацией статуса может привести к повторному сообщению. Поддерживается один bot worker. Коммерческие операции сериализуются общей advisory-блокировкой PostgreSQL; при высоком объёме потребуется переход к упорядоченным блокировкам кошельков.
