# Публикация подписанного APK

Текущий asset — `MelkaDLC-licensed.apk`. Старые `MelkaDLC.apk` и `skinchiki.apk` сохраняются. Реконструкция восстанавливает неизменённый helper из оригинала, выполняет строго ограниченную замену брендовых полей и ожидаемой CRC модуля, затем воспроизводит raw DEFLATE level 9. Полный SHA-256 подписанного APK обязан совпасть до загрузки.

Локальный GitHub CLI смог читать репозиторий, но загрузка на `uploads.github.com` получила HTTP 401. Workflow `Publish verified MelkaDLC APK` выполняет штатную загрузку с токеном GitHub Actions в этом же репозитории.

`recipe.json` содержит только публичные байты подписанного APK и ссылки на неизменённые сжатые данные оригинального публичного APK. Приватный ключ и пароль здесь отсутствуют. `reconstruct.py` проверяет SHA-256 оригинала и восстанавливает точный подписанный файл с проверкой итогового SHA-256. Механизм проверен локально.

Workflow проверяет существование V1.1.0 и сохранность оригинального asset, отклоняет конфликт `MelkaDLC.apk`, проверяет Android SDK apksigner и метаданные, добавляет файл без `--clobber`, скачивает его по публичной ссылке и снова сравнивает SHA-256. Тег и оригинальные файлы не изменяются.

Это доставка уже собранного и подписанного APK; для изменения приложения используйте `android/build.py` и приватный резервный комплект подписи. Наличие recipe не позволяет подписывать новые модификации.
